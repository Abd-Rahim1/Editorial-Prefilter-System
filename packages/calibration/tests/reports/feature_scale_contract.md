# Scientific Feature Scale & Normalization Contract

As required by Architectural Correction #2, this system **does not assume** that semantic features are normalized `0.0–1.0` across all contexts, and explicitly maps out the exact numerical behaviors at every transition.

## 2. Stage-by-Stage Empirical Findings

### Stage 1: Layer 2 Raw Scale (`public.llm_evaluations` & Prompt Templates)
- **Empirical DB State**: Inspection of `public.llm_evaluations` reveals `overall_quality` scores in the range `[0.15, 0.80]`, generated by the active `v5_calibrated_json` prompt (`PromptTemplate id=8`).
- **Scale Risk & Assumption Mitigation**: Legacy prompts (such as `v1_zeroshot_baseline` (`id=2`) or uncalibrated PeerRead models) can produce uncalibrated `[1.0, 5.0]` integer scores. If un-normalized `[1.0, 5.0]` scores enter Stage 2 without calibration or scaling, the derived `risk_multiplier = (1.0 - overall_quality) * total_rules_failed` yields negative interaction values (`-8.0` to `-32.0`), invalidating the tree split thresholds learned during training. Therefore, runtime processing must never blindly assume semantic scores are already `0.0-1.0` normalized unless verified against the active model's expectations.

### Stage 2: Processed JSON Scale (`build_raw_features` in `feature_builder.py`)
- **Interaction Formula Enforcement**: `feature_builder.py` aggregates Layer 1 (`total_rules_failed`, `critical_rules_failed`, `conference`) and Layer 2 outputs into a raw feature mapping.
- **Dynamic Derivation**: If `risk_multiplier` is not explicitly supplied in `raw_override`, `build_raw_features` enforces the exact training-time equation: `(1.0 - overall_quality) * total_rules_failed`. No arbitrary clipping (`min(max(x, 0.0), 1.0)`) or scaling is applied at this stage.

### Stage 3: Prepared Dataset Scale (`data/prepared/v5/dataset.csv`)
- **Exact Empirical Bounds**: As detailed in the summary table above, the authoritative `C2` dataset contains semantic features distributed across sub-intervals of `[0.0, 1.0]`, rule counts distributed across `[0.0, 10.0]`, categorical conference IDs (`0, 1, 2`), and the interaction term `risk_multiplier` spanning `[0.09, 6.40]`.

### Stage 4: Training Scale (`Random Forest C2` vs Linear Models)
- **Active Model Behavior**: For `TrainedModel id=1` (`Random Forest C2`, `best_pipeline.joblib`), the training metadata confirms `"scaler_present": false` and `scaler_path = None`. Tree-based classifiers learn hierarchical decision splits directly on the original prepared feature distributions (`Stage 3`).
- **Scaled Dataset Contrast**: In `data/prepared/v5/X_train_scaled.csv`, all 10 features are Z-score standardized (`mean ~ 0.0, std = 1.0`) via `StandardScaler`. This scaled dataset is utilized exclusively when training linear classifiers (`Logistic Regression`, `Isotonic Regression`, etc.), where gradient convergence and L2 regularization require zero-centered unit variance.

### Stage 5: Online Scale (`preprocess_features` in `feature_preprocessor.py`)
- **1-Row DataFrame Construction**: The online preprocessor takes `raw_features` from `build_raw_features()` and constructs a 1-row `pandas.DataFrame` strictly ordered by `ordered_features` from `feature_schema.json`.
- **Zero-Distortion Policy**: The preprocessor casts input strings/numbers to `float` and sanitizes only `NaN` or `Inf` to documented fallbacks (`FEATURE_DEFAULT_VALUES`). It does not apply any hidden min-max scaling, double-normalization, or `[0.0, 1.0]` truncation, ensuring `100%` fidelity between the serving payload and the loaded model artifact.
